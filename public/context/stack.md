## Configuration

- `next.config.ts`: `reactCompiler: true`, plus a Turbopack rule that runs `@tailwindcss/turbopack` on `*.css`. There is no PostCSS config; the Tailwind integration goes through that loader only.
- `tsconfig.json`: includes `**/*.ts`, so tests are type-checked too. `src/app/layout.tsx` relies on the global `LayoutProps`, generated by Next.
- `eslint.config.mjs`: Next presets with default ignores.
- Fonts through `next/font/google`, which fetches at build time: Plus Jakarta Sans (preloaded), and Inter, Outfit, Fraunces, Nunito, Fredoka (not preloaded, used by specific themes).

## Tests

> **DANGER: do not run `tests/service.test.ts` with the current `.env`.** Its `main()` calls `mongoose.connection.dropDatabase()` on whatever `MONGO_URI` points to, and that is currently a remote cluster. Only run it against a disposable database. See D3.

| File | Covers | Needs a DB |

Both are plain scripts using `node:assert`, with no framework. No runner is installed (`tsx`, `jest`, `vitest` and `ts-node` are all absent), and they need the `@/` alias plus handling of `server-only`, so the intended run command is **Unknown**. **Neither test was run in this audit.**

There are no tests for API routes, validation schemas, `lib/domain/stats.ts`, `computeLongestStreak`, `dayStatus`, or any UI.

## Static checks at audit time

Run without writing to the project: `tsc --noEmit --incremental false` and `eslint .`.

- ESLint: no problems reported.
- TypeScript: one error, `src/app/layout.tsx: Cannot find name 'LayoutProps'`. **Inferred:** environmental, because that type is generated into `.next/types`, and this copy has no `.next` or `next-env.d.ts`.
- The first audit ran neither `next build` nor the app. Both were later run for the redesign: see `ui.md`. With `next-env.d.ts` generated, `tsc` reports no errors. The `.next` folder and `next-env.d.ts` were then removed.

To run the app safely, override the database: `MONGO_URI=mongodb://127.0.0.1:27017/dev npm run dev`. Otherwise it uses the remote cluster in `.env`.

## Development workflow

1. `npm install`
2. Provide `MONGO_URI`, `NEXTAUTH_SECRET` and `NEXTAUTH_URL` in `.env`
3. `npm run dev`, then open http://localhost:3000
4. `npm run lint`; `npx tsc --noEmit --incremental false` (plain `tsc` writes a `.tsbuildinfo` because `incremental` is on)

Deployment: no Dockerfile, `vercel.json` or CI config exists. The README is the unmodified create-next-app text.
